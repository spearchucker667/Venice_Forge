# Venice Forge Documentation

Welcome to the **Venice Forge** documentation tree.

The documentation is organized according to the [Diátaxis framework](https://diataxis.fr) into four distinct categories:

1. **Tutorials (Learning-Oriented)**: Step-by-step lessons for newcomers to build practical competency (e.g., getting started with ST Card Studio, local building).
2. **How-To Guides (Task-Oriented)**: Direct recipes and step-by-step instructions for solving specific operational problems (e.g., troubleshooting, testing, encrypted backup & sync, release signing).
3. **Reference (Information-Oriented)**: Technical descriptions, schema specifications, and contracts (e.g., Venice API OpenAPI specifications, model capabilities, theme schemas, security threat models).
4. **Explanation (Understanding-Oriented)**: Architectural discussions, design rationale, and background context (e.g., memory isolation, character RP architecture, Document Agent runtime).

## Documentation Precedence and Governance

When consulting documentation, follow the repository precedence rules:
1. **Source Code and Runtime Behavior** (`src/`, `electron/`, `package.json`) are the ultimate authority.
2. **Active Governance and Agent Rules** (`AGENTS.md`, `docs/ROADMAP.md`, `docs/summary_of_work.md`).
3. **Architecture and Security Specifications** (`docs/architecture/`, `docs/security/`).
4. **Reference and Integration Specifications** (`docs/reference/`, `docs/DEVELOPMENT/`).
5. **How-To Guides and User Documentation** (`docs/user/`, `docs/DOCS_INDEX.md`).
6. **Historical Records and Archives** (`docs/audits/Records/`, `docs/reports/historical/`, `docs/archives/`) are non-authoritative historical evidence.
