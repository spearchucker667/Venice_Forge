`VF-CAPABILITY-PROVENANCE-2026-08-31 — Deferred capability-token design for provenance-less custom-protocol requests (open; design investigation only).` VF-AUD-20260831-P2-006 closed the documented investigation by recording that `evaluateCustomProtocolAccess()` in `electron/utils/customProtocolAccess.ts` still allows requests with neither `Origin` nor `Referer` because Chromium media elements can omit both. The HANDOFF preferred design is a capability-based scheme: `renderer asks trusted preload/main for media URL → main emits venice-media://<opaque-id>?cap=<short-lived capability> → protocol validates capability + profile + object id → one active renderer/session/profile can use it → expiration/revocation on profile switch/app shutdown`. The capability must be unguessable, local-only, and never persisted in diagnostics. Existing origin/referer checks remain as defense-in-depth. Implementation is intentionally deferred — it requires a coordinated change across the main-process protocol handler, the preload bridge, the `desktopBridge` media helper, and the renderer-side media consumers (`<video>`/`<img>` elements in `MediaStudio`, `ChatTtsPlayer`, `CharacterImageCache`). Until then, the current allowlist-by-mime/path-containment/profile-scope contract remains in place.

`VF-FSM-CLASSIFIER-2026-08-31 — Semantic media classifier backend decision recorded; implementation deferred.` VF-AUD-20260831-P2-009 added `getClassifierCapabilities()` to `src/shared/safety/mediaScreener.ts`. The current production behavior is reported as `semanticImageClassifier: "unavailable" | semanticAudioClassifier: "unavailable" | semanticVideoClassifier: "unavailable"` because no ML backend is registered. The structural heuristic (tracking-pixel, MIME mismatch, magic-byte verification) is the only gate. The decision record at `docs/audits/Records/semantic-media-classifier-decision-2026-09-01.md` selects a **local on-device image classifier** as the canonical next backend, preserving the local-first privacy model and avoiding new network boundaries. Provider-side classification is reserved for re-evaluation only if compliance or accuracy requirements override those advantages. Audio and video semantic classification remain deferred until a mature open or first-party option exists. Implementation is still gated on model/runtime selection, bundle-size acceptance, and supply-chain review.
